1무엇을 하는 앱인가

부스에서 결제한 아이는 번호·QR·비밀번호가 인쇄된 A4 그림 용지를 받는다. 이 종이가 곧 입장권이자 신분증이다.

① 종이에 곤충 그리기→ ② 종이 QR 찍기
이름·설문→ ③ 능력 고르기
종류·출신지·부위 점수→ ④ 그림 촬영
AI 변환 (최대 3번)→ ⑤ 곤충 카드→ ⑥ 랭킹 도전 3판
+ 연습 1판→ ⑦ 랭킹·뱃지·레벨업

아이가 느끼는 핵심

  • "내가 그린 곤충"이 AI 로 멋지게 변함 — 아이가 그린 개수(큰턱 4개 등)는 고치지 않고 살림
  • 곤충 종류마다 다른 필살기, 리듬게임식 타이밍 버튼(퍼펙트/굿)
  • 랭킹 3위→2위→1위로 올라가는 사다리 도전, 이기면 그 순위를 차지
  • 다시 오면 레벨업 + 능력 포인트, 카드 테두리가 은→금→다이아
  • 뱃지 38개, 중간보스·보너스 스테이지, 되받아치기

운영자가 필요했던 것

  • 개인정보 0 — 이름(닉네임)만 받고 원본 사진은 저장 안 함
  • 참가권 금액별 게임 횟수 (직원 화면에서 올려줌)
  • 태블릿 공용 사용 — 게임이 끝나면 자동 로그아웃
  • 부스 모니터용 실시간 순위판, 대기 화면 홍보 영상
  • 시상용 원본 그림·A3 포스터·포토프린터 카드 뽑기
  • 당첨자 연락은 카카오톡 채널 1:1 (번호로 특정)

중요한 설계 원칙: 저장된 능력치를 믿지 않는다. 배틀·카드는 매번 입력값(종류·부위·출신지·진화·레벨·포인트)에서 statsForInsect() 로 다시 계산한다. 규칙이 행사 중에도 여러 번 바뀌었는데, 이 덕분에 옛 곤충도 새 규칙으로 자연스럽게 따라왔다.

그림 저장과 용량

  • Gemini 결과(1024px PNG, 약 2.8MB base64)를 받자마자 JPEG q92 로 재인코딩 → 약 0.47MB. 해상도는 포스터·피규어 때문에 유지.
  • 그림은 insects.image_base64 컬럼에 텍스트로 저장 (Storage 미사용). 목록 조회에서는 이 칸을 빼고, 필요한 그림만 따로 받는다.
  • 순위판·홍보 영상은 그림을 기기 IndexedDB 에 캐시해 다시 받지 않는다.
  • 행사 2일 뒤 DB 전체 43MB. 원본 사진은 저장하지 않음 (아동 개인정보 최소화).

신원 확인 방식

  • 로그인 계정 없음. 종이 번호 + 4자리 비밀번호. 비밀번호는 저장하지 않고 번호에서 HMAC 으로 계산(서버 전용 비밀값).
  • QR 에 번호와 비밀번호가 들어 있어 찍으면 바로 입장. 손으로 칠 때만 비밀번호 확인.
  • 기기에는 localStorage 로 "지금 이 기기의 아이"를 기억. 공용 태블릿이라 자동 로그아웃 규칙이 따로 있다(5장).
  • 번호 구간 약속: 900~999 테스트(테스트끼리만 만남), 450~500 직원 캐릭터.

4게임 시스템

능력치

HP · 공격력 · 수비력 · 지능 · 회피력 (+ 성실함). 계산 순서: 부위 점수(1~5) → 성장단계 → 출신지 → 특별 진화 → 레벨 → 포인트·보너스.

  • 곤충 종류 6개(장수풍뎅이·사슴벌레·사마귀·벌·나비·기타) — 종류가 필살기를 정한다. 공격형 4종, 수비형 2종.
  • 출신지 5개 — 4개가 가위바위보 상성(이긴 쪽 +7%), 1개(운석충돌)는 상성 없음.
  • 특별 진화 — 아이가 실제보다 많이 그린 부위(큰턱 4개, 다리 8개 등)는 얻는 만큼 잃게. 종마다 정상 개수가 다름(나비 날개 4장).

배틀

턴제가 아니라 점수 대결이다. 화면의 HP 바·공격 연출은 이미 계산된 결과를 보여주는 순서일 뿐이다.

기본 점수100 × HP^0.4 × 공격^0.3 × 수비^0.3 × 운 × 크리티컬 × 상성. 운·크리는 배틀 시작 때 한 번만 굴림
필살기공격형: 상대 점수 20~30% 깎기(크리 50~60%). 수비형: 막기 + 되받아치기(성공 50%). LV3 부터 반대 형 기술 하나 더
타이밍 버튼고리가 4초 동안 일정하게 줄어 2초에 겹침. 퍼펙트 ±250ms ×1.35 · 굿 ±900ms ×1.1. 고리는 CSS 가 그리고 JS 는 누른 시각만 잼(폰 버벅임 방지). 모양·위치 무작위
되받아치기배틀의 30% 에서 2.5배 빠른 고리, 퍼펙트면 상대 공격을 그대로 반사
회피·성실함회피력 % 로 상대 필살기를 통째로 피함(최대 60%). 성실함은 필살기 피해 감소
역전 장치레벨이 낮으면 크리티컬 +2%/레벨, 낮은 레벨일수록 "필살기 한 번 더" 확률 높음
랭킹 규칙랭커를 이기면 그 아이 최고 점수 +1 로 기록 → 그 순위 차지. 3위 안은 상대 점수 ×1.14(더 어렵게)

성장

  • 레벨당 경험치 100. 배틀 경험치는 LV1 100% → 레벨마다 ×0.7. 다시 오면 LV5 까지 바로 레벨업.
  • 레벨업 때 포인트 3개를 아이가 직접 분배. 어디에 몰아도 승률 차이가 같게(약 55%) 맞춤.
  • 수비하는 곤충도 경험치(도전자의 20%, 하루 1레벨까지) — 상위 곤충 눈덩이 방지.
  • 뱃지 38개 + 10·15·20개 보상 버프. 게임 수에 따라 열리는 뱃지 수 상한.

밸런스를 어떻게 맞췄나

배틀 엔진(lib/battle-engine.ts)이 순수 함수라 Node 로 수천 판씩 돌려 승률을 잰다. 목표치: 전부 5점 vs 전부 1점 55~60%(조금만 유리), 곤충 종류·출신지끼리 48~52%, 2~5회차 vs 1회차 약 65~70%. 이 과정에서 실제로 잡은 구멍 — 수비형 곤충 승률 0.7%(반격 추가로 해결), "필살기 한 번 더" 때문에 부위 점수가 낮을수록 이기는 역전 현상(45%) 등.

퍼펙트 판정 글자가 아무에게도 안 보임화면 전환이 연출보다 먼저 일어남. 점수엔 반영돼 있었음 → 연출 순서도 테스트 대상

6알려진 한계와 기술 부채

"3주 안에, 부스에서 확실히 돌아가게"를 우선해 의도적으로 감수한 것들이다. 정식 출시 전에 손봐야 한다.

보안·공정성 — 가장 먼저. Supabase RLS 가 꺼져 있고 브라우저가 anon 키로 직접 쓴다. 게임 횟수·레벨·점수·참가권 등급을 모두 브라우저가 계산해 저장하므로, 마음먹은 어른은 기록을 고칠 수 있다. 상품이 걸린 랭킹이라 정식 서비스에서는 배틀 판정과 기록 쓰기를 서버로 옮겨야 한다. 직원 암호도 아이 오작동 방지 수준이다.

7같이 이야기하고 싶은 것

① 플랫폼

  • 계속 웹(PWA)으로 갈지, 앱(React Native / Flutter / 게임 엔진)으로 갈지
  • 현재 연출은 CSS 애니메이션 — 앱에서 더 화려하게 하려면 무엇이 맞는지
  • "27년 초 앱 출시" 안내를 이미 했고, 2만원 이상 아이들에게 캐릭터 보존을 약속함 → 지금 DB 를 새 앱으로 옮기는 방법

② 서버와 공정성

  • 배틀 판정을 서버로 옮기되, 타이밍 버튼 같은 손맛은 유지하는 방법
  • 계정 체계(보호자 로그인 + 종이 QR 연결)
  • 결제(참가권·인앱) 연동

③ AI 그림

  • "아이 그림을 존중하면서 멋지게" — 프롬프트만으로의 한계(종류가 섞여 나오는 문제 등)
  • 장당 약 90원. 사용자가 늘 때 비용 구조, 캐시·생성 횟수 정책
  • 피규어·포스터용 고해상도(현재 1024px → 업스케일로 보완)

④ 콘텐츠 확장

  • 미니게임(참나무 수액 연타 등), 도감, 키우기
  • 식물·어류·공룡 시리즈로 같은 엔진 재사용
  • 오프라인 체험(채집·사육)과 앱 캐릭터 연결

베타에서 검증된 것

  • 종이 그림 → QR → AI 캐릭터 → 배틀까지 한 아이당 수 분 안에 끝나는 흐름이 부스에서 실제로 돌아감
  • "내 그림이 멋지게 변한다"와 "랭킹 1위를 뺏는다"가 재방문(레벨업) 동기로 작동
  • 2일 동안 서버 비용: Supabase Pro 한 달 $25 + Gemini 약 ₩7,000 + Vercel 무료
