## 1. 곤충 그림 "마지노선" 확실히 알기 + 무료/유료 차이

**목표**: "이 정도 그림이면 합격, 이 밑이면 안 된다" 기준선과, 무료/유료 그림 도구의 차이를 숫자·눈으로 확인해서 표로 남긴다.
❓ 마지노선 = AI 그림 **품질의 최저 합격선** 으로 읽었다. (다른 뜻이면 알려줘 — 예: 비용 마지노선, 하루 장수 마지노선)

### 1-1. 합격선(체크리스트) 정하기 — Jin + Claude
행사 때 실제로 터진 문제를 기준으로 만든다. 항목마다 ○/× 로 채점.
- [ ] 고른 종류가 한눈에 그 곤충으로 보인다 (나비인데 얼굴이 사슴벌레 → ×)
- [ ] 아이 그림의 모양·색이 반영됐다 ("내가 그린 거랑 다르다" 방지)
- [ ] 부위 개수가 지시와 맞다 (큰턱 4개 같은 특별 진화는 지시대로)
- [ ] 그림 안에 글자·숫자·로고·워터마크가 없다
- [ ] 다리·더듬이가 너무 가늘지 않다 (3D 프린팅 피규어용, 1위 상품)
- [ ] 해상도 1024px 이상 (포스터·피규어 쓰려면 원본이 더 클수록 좋음)
- [ ] 1장 만드는 시간 20초 안쪽 (부스 줄)

### 1-2. 무료 vs 유료 비교 테스트 — 같은 입력으로
같은 아이 그림 사진 6장(`docs/edu-onepager/shots/kid-*.jpg`) + 같은 프롬프트로 만들어서 나란히 놓고 채점.

| 비교 대상 | 확인된 것 | 확인할 것 |
|---|---|---|
| **유료 API** (`gemini-3.1-flash-image-preview`, 행사 때 쓴 것) | 장당 약 $0.067(≈90원), 1024px | 장당 실제 청구, 속도, 위 체크리스트 점수 |
| **무료 Gemini 앱** (gemini.google.com) | 10/7 Jin 이 만든 공룡 그림: 1024×1024, **오른쪽 아래 별(✦) 로고가 박혀 나옴**, 화질 괜찮음 | 하루 한도, 사진 넣고 그리기 되는지, 상업 이용·로고 약관, 앱(코드)에서 자동 호출 가능한지 |
| **무료 API 등급** | 이미지 생성 모델은 무료 할당량 **0** → 결제 필수 (CLAUDE.md 기록) | 요즘도 그런지 AI Studio 에서 다시 확인 |
| (선택) 다른 이미지 모델 | — | 필요하면 후보 1~2개 |

⚠️ "무료 앱에서 화질 괜찮았다" ≠ "우리 앱이 무료로 쓸 수 있다". 무료 Gemini 앱은 사람이 손으로 쓰는 곳이라 **우리 앱에 연결하는 건 별개 문제**다 (약관·자동화 가능 여부 확인 필요).

### 1-3. 결과물
- [ ] 비교표 1장 (점수 · 속도 · 장당 비용 · 한도 · 워터마크 · 앱 연결 가능 여부)
- [ ] **마지노선 결정**: 어떤 도구를 쓰고, 어떤 점수 밑이면 "다시 만들기"로 돌리는지
- [ ] 비용 예상: 장당 × 사람당 최대 3번(`MAX_ATTEMPTS`) × 예상 인원 (곤충·공룡·어류·식물 4개 앱이면 ×4 로 다시 계산)

### 1-4. 막힌 점
- 🔴 **Claude 컨테이너에는 진짜 Gemini 키가 없다** (테스트용 가짜 키만 있음). 유료 API 비교를 Claude 가 돌리려면 클라우드 환경 변수에 `GEMINI_API_KEY` 를 넣어야 한다 (채팅에 붙여넣지 말 것). 안 넣으면 Jin 이 AI Studio 에서 직접 돌리고 그림만 올려주기.
- 눈으로 보는 합격 판정은 Jin 몫 (Claude 는 "그림이 멋있는가" 를 대신 못 봄 — 체크리스트 일부만 자동 확인 가능).

## 2. 곤충 · 공룡 · 어류 · 식물 — 폴더 나누기 + 앱마다 "재미 / 교육" 노선 선택

**목표**: 4가지 주제 앱을 폴더로 나누고, 각 앱에서 **재미(게임) 노선** 과 **교육 노선** 을 고르면 화면·기능이 바뀌게 한다.
교육기관 소개서(`docs/edu-onepager/`)가 이미 "게임 요소를 뺀 교육 노선" 얼개다.

   | 배틀·랭킹·상품 | 있음 | 없음 |
   | 필살기·타이밍·뱃지·소리 | 있음 | 없음 |
   | 몸 구조 고르기 · 환경 고르기 · 능력 도형 | 있음 | **있음 (핵심)** |

3. **"폴더 나누기" 범위**: ① 한 저장소 안에서 주제별 폴더(코드 공유) ② 주제마다 저장소·배포 따로. Claude 추천은 ① (4개를 따로 두면 버그를 4번 고쳐야 함)
